# vFlow v4.3.0-dev — Refactor Integrity B6 Audit

## Purpose

B6 is a broader post-refactor integrity pass performed after A5. It deliberately targets defects that helper-level tests can miss: stale presentation state, UI/model ownership splits, Tk objects crossing into plain analysis state, notebook teardown, scale/layout transitions, asynchronous variable-trace failures, degenerate datasets, and filesystem failure boundaries.

A5 began this pass with **1,109 passing tests**. Static extraction/wiring scans found no unresolved host attributes in the decomposed UI/controller/render boundaries, but real Tk/Matplotlib generated-data probes found additional runtime defects.

## Confirmed defects found and fixed

### B6-01 — Clear All left stale rendered biological data visible

`FlowRenderer.refresh()` returned immediately when both channels were unset. `clear_all_files()` correctly removed the data and reset the channels, but the old scatter/title remained visible because no render reset occurred.

**Fix:** when the host has no loaded files, the renderer now rebuilds/clears the axes and displays `No data loaded.` rather than returning with stale artists.

### B6-02 — Clear All left stale channel selector presentation state

The channel-menu updater intentionally returns when there are no loaded files, so the visible combobox values and `StringVar`s kept the previous dataset's channel names after a complete clear.

**Fix:** Clear All now explicitly empties both menu value lists and visible channel variables.

### B6-03 — Locked scale state leaked across datasets

A locked X/Y range survived Clear All. Loading a new dataset with a very different numeric range then reapplied the old limits, making valid new data appear absent/blank.

**Fix:** Clear All now turns lock off, clears `_locked_xlim`/`_locked_ylim`, and hides the lock controls before the next render/load.

### B6-04 — Closed sub-gate tabs leaked their Tk widgets

`ttk.Notebook.forget()` removes a tab from the notebook but does **not** destroy its child widget. Repeated sub-gate exploration therefore accumulated forgotten `FlowApp` widget/canvas trees and their references.

**Fix:** `_close_tab()` now resolves the child widget, cancels pending callbacks, removes the app, forgets the tab, and explicitly destroys the child widget. An 8-cycle real-Tk teardown test verifies notebook children do not accumulate.

### B6-05 — Live Tk gate state could cross the tab-manager analysis boundary

The ordinary double-click path already supplied a Tk-free gate snapshot, but `FlowTabManager.open_subgate_tab()` could be called with a live gate dictionary containing `tk.BooleanVar`. `AnalysisState.set_population_context()` deep-copies provenance, which then fails with `TypeError: cannot pickle '_tkinter.tkapp' object`.

**Fix:** `_load_filtered()` defensively converts any parent gate through `GateDefinition.from_live_dict(..., variable_types=(tk.Variable,))` before analysis-state storage. The normal path remains bit-for-bit plain-data compatible.

### B6-06 — Layout rebuilds could emit log-axis teardown warnings

Rebuilding axes (notably when toggling marginals) called `Figure.clear()` while shared axes could still be log-scaled. Matplotlib could warn while trying to reset non-positive limits during shared-axis destruction.

**Fix:** `_setup_axes()` normalizes existing axes to linear scale before clearing the figure, matching the A5 render-lifecycle transition safeguard.

### B6-07 — Gate-session save filesystem failures escaped the UI

After the save workflow was moved to `ProjectDataLoadCoordinator`, malformed gate validation was handled but an `OSError` while opening/writing the selected destination propagated out of the button callback.

**Fix:** gate-session filesystem writes now report an actionable `Save Gates` error and return cleanly. Programming/validation errors are not swallowed by a blanket `except Exception`.

### B6-08 — Constant/degenerate Density data crashed asynchronously

Generated constant-channel data exposed a real Density failure. A degenerate percentile span produced a non-strict interpolation grid, and `RegularGridInterpolator` raised `ValueError`. When triggered by a scale `StringVar.trace_add`, the exception appeared asynchronously in Tk rather than as a controlled render fallback.

The old AP07 test explicitly encoded this crash as a historical expected boundary.

**Fix:** Density and Contour payload builders now detect non-finite, zero-span, or machine-resolution-non-monotonic grids and use the existing deterministic Dot fallback. The historical test was intentionally updated: preserving a known runtime exception is no longer a desired compatibility invariant.

### B6-09 — Duplicate refactor decorator debris

A duplicated `@staticmethod` remained on `_kde_valley_supported` after extraction/refactoring.

**Fix:** removed the redundant decorator. No behavioral effect.

## Result

The cumulative automated suite is **1,115/1,115 passing** after B6. No missing extracted-host attribute references were found, no asynchronous errors occur in the B6 edge/state validators, and the retained A5 GUI regressions remain green.

This is a materially broader runtime audit than A5, but it is not a mathematical claim that arbitrary future files or every OS/Tk/Matplotlib combination can contain no latent defect. The important change is that the newly discovered failure classes are now encoded as permanent tests/validators rather than relying on one-off manual verification.
