# vFlow v4.3.0-dev Accuracy Hardening A4 Audit

## Purpose

A4 is a second scientific-accuracy audit starting from the certified A3 Gate Axis
Preservation checkpoint.  It is intentionally not a feature or architecture pass.
The target class is *plausible but wrong* output: paths that can return a believable
plot, population, percentage, direction, or aggregate while silently omitting,
substituting, reshaping, or misidentifying data.

The certified A3 behavior remains the baseline unless a defect-triggering case is
explicitly covered below.

## Confirmed accuracy defects corrected

### A4-01 — Compensation metadata could be missed or overinterpreted

Older FCS compensation metadata such as `$COMP`, and historical compensation
keyword forms, could pass without the safety notice that already existed for
newer spillover metadata.  Conversely, compensation metadata alone does not prove
that stored DATA are uncompensated.

**Correction:** the reader records compensation-related metadata across supported
historical/current keyword forms.  The application and batch workflow now issue a
neutral **compensation state requires verification** warning/provenance marker.
vFlow does not claim that compensation is absent, present, applied, or reversed.

### A4-02 — Valid FCS integer values with unused high bits could be rejected

The integer decoder validated the complete storage word against `$PnR`.  FCS
integer channels may have storage bits above the significant range; those unused
high bits are not part of the measured value.

**Correction:** unused high bits are masked in integer space before conversion,
then the significant value is range-checked.  Values still outside `$PnR` fail.
Ranges that cannot be represented exactly in float64 fail rather than lose integer
precision silently.

### A4-03 — Malformed inactive saved gates could become different future gates

Inactive rectangle/ellipse/polygon/crosshair state could contain malformed or
non-finite geometry.  Historical sanitization could drop or substitute those
values because the gate was not currently applied; applying it later could then
analyze a different geometry from the saved one.

**Correction:** geometry and threshold state must round-trip losslessly even when
inactive.  Malformed inactive gates are rejected/skipped rather than reshaped.

### A4-04 — Loading A/B gates while viewing B/A bypassed A3 swap semantics

A3 fixed an interactive true X/Y exchange, but loading a saved A/B gate session
while the current view was B/A still passed through the older ordered-context
load path.

**Correction:** a pure reversed channel pair on session load uses the same gate
and analysis-context transposition semantics as A3.  Unrelated channel changes
remain incompatible and do not rebind the gate.

### A4-05 — Undefined circular mean direction could become a plausible angle

For exactly antipodal/symmetric vectors the mean resultant is zero and mean
direction is mathematically undefined.  `atan2` on floating-point round-off could
manufacture a direction such as 90 degrees.

**Correction:** numerically zero mean resultant returns no mean direction.  The
reported direction is blank/None rather than a round-off artifact.

### A4-06 — Zero transform-valid-event samples could disappear from statistics

A sample whose rows all became invalid under the active transform could be omitted
from a gate-stat result, silently shrinking sample provenance.

**Correction:** the sample remains represented with analysis denominator `Total=0`
and explicit input/transform-excluded provenance.

### A4-07 — Single-gate export provenance did not fully identify analysis context

Exports could report percentages without enough gate/transform information to
reconstruct which gate and transform universe produced them.

**Correction:** additive provenance now includes gate id/name/type, full Y threshold
set, geometry where applicable, X/Y scale, cofactor, per-axis transform parameters,
input total, transform-valid total, transform-excluded count, and compensation
verification metadata.

Existing percentages retain the historical transform-valid denominator.

### A4-08 — KDE/Otsu status percentages used a different universe/boundary rule

Displayed threshold percentages could include finite raw values that were invalid
under the selected transform (for example nonpositive values on log) and used `<`
where the actual lower gate region uses `<=`.

**Correction:** status percentages use the same transform-valid universe and
boundary inclusion as the resulting gate.

### A4-09 — No-common-channel multi-file analysis could silently fall back

When multiple active files shared no safe analysis channel, channel selection could
fall back to the first file.  Downstream calculations then had paths that skipped
incompatible files, yielding a plausible result for only a subset.

**Correction:** the axes are cleared when there is no safe common channel.  The
user must deactivate incompatible files or resolve channel nomenclature before
analysis.

### A4-10 — Duplicate FCS stain labels could be falsely matched across files

Within one FCS file duplicate stain labels are disambiguated with suffixes such as
`CD3_1`.  Across files those suffixes can follow parameter order rather than a
stable biological detector identity.

**Correction:** auto-disambiguated duplicate FCS channel names remain usable in a
single file but are ineligible for automatic multi-file matching until explicit
nomenclature mapping resolves the identity.

### A4-11 — Unnamed CSV measurement columns could be falsely matched across files

A legitimate numeric blank-header measurement may be preserved by pandas under a
synthetic name such as `Unnamed: 0`.  The same synthetic name in another CSV does
not establish biological identity.

**Correction:** preserved unnamed measurements remain single-file usable but are
marked ambiguous for automatic multi-file matching until nomenclature is resolved.

### A4-12 — Heterogeneous concatenation could expose partial-source channels

Heterogeneous concatenation is intentionally supported, but a numeric column that
exists in only some constituent sources becomes an ordinary column with NaN blocks
for the others.  Selecting it could silently analyze only the source files that
actually contain measurements.

**Correction:** axis candidates are numeric measurement columns only; provenance
columns (`Source_File`, `Source_Path`) are never axes.  In a concatenated dataset,
a channel with no finite measurements for one or more constituent sources is
hidden from axis selection.  Heterogeneous concatenation itself remains allowed.

### A4-13 — Forced axis fallback could collapse X and Y onto one channel

When an old X channel became unavailable while the old Y remained valid, automatic
fallback could set both axes to the same surviving channel.

**Correction:** only forced fallback avoids this collapse when at least two safe
channels exist.  An explicitly user-selected same-channel X/Y plot remains allowed.

### A4-14 — Batch region partitions could shrink the denominator through gaps

A1 already rejected overlapping batch regions.  A disjoint set of region masks
could still omit transform-valid rows and use the smaller covered union as the
reported denominator.

**Correction:** Batch Stats region masks must be both disjoint **and collectively
exhaustive** over the established transform-valid universe.  Overlap or gaps abort
the sample instead of changing its denominator.

### A4-15 — Batch denominator provenance was ambiguous

`Total_Cells` is the transform-valid analysis denominator, not necessarily the raw
number of rows acquired/read.  A first hardening attempt also demonstrated why
provenance must be captured before the transform filter rather than reconstructed
after it.

**Correction:** batch output now distinguishes:

* `Source_Total_Cells` — rows read from the source file;
* `Input_Total_Cells` — rows entering the current population after lineage;
* `Total_Cells` — transform-valid denominator used by reported percentages;
* `Transform_Excluded_Cells` — input rows excluded by transform validity.

The historical percentage denominator is unchanged.

### A4-16 — Subgating could build a population from only compatible active files

If stale/inconsistent UI state reached subgate resolution, missing X/Y channels in
one active file could be handled by continuing with compatible files.

**Correction:** any active-file channel mismatch aborts subgate population
construction.  No child population is built from a partial active-file subset.

### A4-17 — Main single-gate/multi-shape statistics could aggregate a subset

The same legacy `missing channel -> continue` pattern existed in main gate stats and
multi-shape partition display.

**Correction:** analysis requires the current X and Y channels to be present in all
active files before computing either result.  Otherwise the calculation fails
closed rather than omitting incompatible samples.

### A4-18 — Invalid analysis context could leave a stale plot visible

When channel validation cleared X/Y, `FlowRenderer.refresh()` could return before
clearing the axes, leaving the previous biological plot visible even though it no
longer represented the active files.

**Correction:** an invalid/no-shared-axis context actively clears the prior plot,
shows an unavailable-analysis message, and flushes the canvas.

### A4-19 — Auto-gating could use a compatible subset under stale state

Although the channel-menu safeguards should prevent this in normal UI flow, stale
or injected state could still reach auto-gate collectors that concatenated only
files carrying the selected channels.

**Correction:** all active files must contain both selected axes before derivative,
Otsu, GMM Multi, or cluster auto-gating proceeds.

### A4-20 — Polar centroid auto-detection could still guess unmatched identities

A1 fixed positional X/Y cross-wiring.  The remaining unmatched-name case could
still return a guessed mapping in sparse schemas.

**Correction:** auto-detection does not invent a pairing when X/Y identities cannot
be matched; explicit selection is required.

## Hypotheses investigated and deliberately rejected

### R1 — “Ignore `$PnG` for floating-point FCS DATA”

**Rejected.** FCS 3.1 implementation guidance includes floating-point examples in
which scale values are obtained using `$PnG`.  Applying the declared gain is not,
by itself, evidence of double-scaling.  No production change was made.

### R2 — “Require identical schemas for all concatenated CSV files”

**Rejected.** This would break a valid workflow in which one source legitimately
contains an additional measurement column.  A4 instead prevents structurally
partial channels from being used as pooled analysis axes.

### R3 — “Compensation metadata means compensation is not applied”

**Rejected.** Historical FCS compensation metadata can also describe compensation
performed electronically.  The application now reports a verification requirement,
not a definitive compensation state.

## Residual scientific/workflow risks — not silent defects

1. **Compensation remains an upstream workflow responsibility.** vFlow detects and
   reports compensation-related FCS metadata but does not automatically apply,
   reverse, or infer a compensation matrix/state.
2. **Unsupported FCS encodings remain compatibility limitations.** They must fail
   explicitly rather than be approximated.
3. **Transform-valid denominators are deliberate.** Percentages continue to use
   the events valid under the active analysis transform.  A4 makes the source,
   input, valid, and excluded counts explicit rather than changing the science.
4. **Explicit nomenclature is required for ambiguous cross-file identities.** A4
   prefers refusing automatic aggregation over guessing detector identity.

## Structural scope

A4 does not reopen the controller decomposition, performance behavior, standard
Logicle design, A3 gate-axis semantics, or unrelated UX.  Changes are limited to
scientific/result integrity, provenance, and fail-closed behavior around confirmed
accuracy risks.
