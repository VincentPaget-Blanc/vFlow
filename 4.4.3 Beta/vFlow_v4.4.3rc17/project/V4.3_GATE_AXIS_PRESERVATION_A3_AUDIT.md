# vFlow v4.3 Gate Axis Preservation A3 Audit

## Defect

Applied gates were bound to an ordered analysis context. A gate created under `X=A / Y=B` therefore failed `_gate_context_matches()` after the user selected `X=B / Y=A`, even though the same two biological channels were still being analysed. Rendering and statistics correctly excluded an incompatible gate according to that old rule, so the observable symptom was that gates disappeared on an X↔Y swap.

That behavior was inaccurate for an axis inversion/swap because the gate can be transposed without changing the underlying selected population.

## Corrected behavior

`plan_axis_apply()` now distinguishes a true swap from a real channel replacement.

A true swap requires all of the following:

1. both previous channels exist;
2. the previous channels are distinct;
3. new X equals previous Y; and
4. new Y equals previous X.

For that case only, `FlowApp.apply_axes()` performs a transactional channel-affine transposition.

### Gate geometry

- Rectangle / ellipse: `(x0,y0),(x1,y1)` -> `(y0,x0),(y1,x1)`.
- Polygon: each `(x,y)` vertex -> `(y,x)`.
- Crosshair: Y thresholds become X thresholds and X thresholds become the appropriate scalar/multi-Y representation. Effective enabled/disabled threshold semantics are preserved, including legacy length-mismatch fallback behavior.
- GMM overlay metadata: `gmm_x_params` and `gmm_y_params` are exchanged.

### Analysis context

The following values move with the channel:

- `x_channel` / `y_channel`;
- `x_scale` / `y_scale`;
- `x_transform_params` / `y_transform_params`;
- locked X/Y limits.

The shared cofactor is unchanged. Gate `_analysis_context` provenance is rebound to the fully transposed current context only after the transposition plan succeeds.

### Recompute path

After commit, vFlow runs the existing `_analysis_context_changed()` path, which invalidates analysis caches, recomputes compatible gate statistics and refreshes rendering.

## Failure safety

All affected-gate transposition plans are built before channels, transforms or gate geometry are changed. If a gate contains invalid axis geometry/state and cannot be planned safely, the swap is rejected before gate mutation.

The scale combobox variables have write traces, so A3 suppresses those callbacks while synchronizing both scale controls. This avoids an intermediate half-swapped scientific context.

## Explicitly unchanged behavior

A real channel replacement is not treated as a swap. For example:

- `A/B -> C/B`
- `A/B -> A/C`
- `A/B -> C/D`

continues to leave A/B gates attached to their saved context and therefore inactive in the new channel context.

A3 does not make arbitrary transform changes gate-compatible. A polygon gate is defined together with its transform context, and silently rebinding it to an unrelated scale can redefine its population. During a true X↔Y swap, the transforms move with their channels specifically to preserve the original population.

## Verification

New regression coverage verifies:

- true-swap detection versus channel replacement;
- complete axis-context transposition;
- crosshair threshold activity and GMM metadata transposition;
- rectangle / ellipse / polygon geometry transposition;
- FlowApp callback behavior;
- nonlinear Gating-ML Logicle parameter movement;
- locked-limit movement;
- A/B -> B/A -> A/B round-trip restoration;
- unchanged behavior for a genuinely new channel.

A dedicated deterministic validator performed 480 membership-preservation comparisons across four gate types and three analysis contexts.
