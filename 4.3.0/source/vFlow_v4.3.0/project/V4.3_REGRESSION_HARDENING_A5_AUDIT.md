# vFlow v4.3.0-dev — Regression Hardening A5 Audit

## Purpose

A5 is a post-refactor runtime audit initiated after interactive application testing exposed severe regressions despite the A4 suite being fully green. The pass treats the real application render/controller chain as an independent test surface and adds generated-data GUI checks so controller-composition and Matplotlib state bugs cannot remain hidden behind unit-level characterization.

The starting A4 checkpoint reported 1102/1102 passing tests. Its uploaded ZIP SHA-256 was `6a2b90bcf2728eccabc07af24e06fce5c173a785a23314b741a70c8b5763b357`. A5 reproduced the user-visible failures before changing production behavior.

## Audit surfaces

The pass exercised:

- FlowApp → FlowRenderer → GateInteractionController composition;
- gate preview/handle-cache creation after a real canvas draw;
- X/Y scale changes across linear, log, asinh, Gating-ML Logicle and both historical transforms;
- gate applicability/recomputation across transform changes versus true channel changes;
- scale changes while a gate is inactive on another channel and subsequent return;
- rectangle, ellipse, polygon and crosshair creation through real click/motion/release callbacks;
- handle resize and whole-gate movement;
- Dot, Density and Contour render paths;
- marginal/shared axes;
- lock/fit/display state interactions;
- two-file overlay/cycle and active-file changes;
- gate session save/reload across transform changes;
- KDE/Derivative, Otsu, GMM Multi and HDBSCAN auto-gating;
- refactor-era unresolved globals and stale method-call targets;
- A4 accuracy, A2 science-method and A3 axis-swap invariants;
- frozen scientific/FCS/render fingerprints.

## A5-01 — gate rendering was broken by a missing composed-controller dependency

### Reproduction

A real generated-data Tk/Matplotlib render with an applied gate reached `GateInteractionController.preview_gate()`, then `rebuild_handle_px_cache()`, and raised:

```text
NameError: name 'handle_cache_entries' is not defined
```

This directly explains the observed “gates do not appear” behavior. The previous suite did not execute this complete render path.

### Root cause

During controller decomposition, `rebuild_handle_px_cache()` moved into `GateInteractionController`, but the corresponding `vflow.core.gates.handle_cache_entries` import did not move with it.

### Correction

The dependency is explicitly imported by the composed controller. A permanent regression test executes `preview_gate()` with a real Matplotlib axes object and verifies the handle cache is built.

## A5-02 — stale Matplotlib log state could reverse an axis during scale transitions

### Reproduction

A generated positive wide-dynamic-range dataset was rendered through a 36-combination X/Y scale matrix. A transition such as `log -> asinh` could leave the transitioning axis with reversed limits, for example a high value followed by a negative lower value, while the opposite axis remained ordered.

### Root cause

The retained-axis rendering optimization intentionally avoided `Axes.clear()` to preserve expensive axis state. During a scale identity change, however, the live Matplotlib axis could still be `log` while the reset path tried to install a neutral range containing zero. Matplotlib correctly rejected zero on a log axis, and the previous limits survived into the new transform.

### Correction

- Full reset now temporarily linearizes both live axes before clearing/resetting them.
- A new compatibility predicate permits retained-axis reset only when the live Matplotlib X/Y scales already match the requested target scales.
- Log targets use the conservative full-reset path.

The 36/36 generated GUI matrix now verifies ordered finite limits and monotonic screen-space transforms for every combination.

## A5-03 — gate applicability incorrectly depended on display-transform identity

### Reproduction

A gate created on X=A / Y=B disappeared when only asinh/Logicle/cofactor/display-scale settings changed. The same geometry engine is capable of evaluating/re-rendering that gate under the new display transform.

### Root cause

`gate_context_matches()` reused strict provenance equality over channels, scales, cofactor and Logicle parameters as the definition of runtime applicability. That conflated two different concepts:

- **provenance equality:** is this exactly the same analysis transform context?
- **gate applicability:** is this gate still associated with the same ordered measurements?

### Correction

Strict full-context equality remains available for provenance checks. Runtime gate applicability is now based on ordered X/Y channel identity. When those channels match, a changed transform context rebinds the live gate context and the gate is recomputed. A genuinely different X or Y measurement keeps it inactive.

This also fixes the edge case where the user temporarily changes channel, changes scale while the gate is inactive, and then returns: the gate is not stranded by the scale setting from the unrelated channel view.

Existing A3 true-axis-swap semantics remain intact and the 480-case axis-swap validator still passes.

## A5-04 — two auto-gate paths retained a deleted refactor method call

### Reproduction

Generated clustered data triggered immediate `AttributeError` in both KDE/Derivative and Otsu auto-gating because they called `_axis_transform_params()`, which no longer exists on `FlowApp`.

### Root cause

The refactor replaced that API with `_transform_params_for_axis()` but four call sites were not migrated.

### Correction

All stale calls were replaced with `_transform_params_for_axis()`. Generated runtime checks now execute all four auto-gate families and require applied gates, statistics and visible preview artists without messagebox errors.

## Static refactor-wiring audit

A5 also scanned the package for refactor-shaped failures beyond the reproduced bugs:

- unresolved global names in production modules;
- unresolved `self.<method>()` targets in FlowApp, GateInteractionController and FlowRenderer;
- unresolved host method targets used by composed controller/renderer classes.

The resulting audit is `PASS`. The only FlowApp dynamic call target encountered is the intentional callable attribute `_last_auto_gate_fn`, not a missing method.

## Behavior deliberately preserved

A5 does not change:

- FCS decoding semantics;
- percentage denominator semantics;
- compensation policy;
- historical transform formulas;
- Gating-ML Logicle mathematics;
- true X/Y axis-swap gate transposition semantics;
- saved scientific lineage semantics;
- frozen reference scientific fingerprint.

The gate applicability change is specifically a UI/runtime correction: transform changes on the same ordered channels recompute gates; different channels make those gates inactive.

## Validation outcome

No failures remain in the audited generated-data/controller/render/session paths after the fixes. The cumulative suite is 1109/1109 passing, and all frozen scientific/FCS/render reference probes remain unchanged. This is strong regression evidence for the audited surfaces, not a claim that arbitrary future environments or untested inputs can contain no defects.
