# vFlow v4.3.0-dev — Accuracy / Scientific Hardening Audit A1

## Purpose

This checkpoint follows the completed v4.3 controller-decomposition Milestone 7 and changes scope from architecture to scientific/accuracy hardening. The objective is to find code paths that can silently change decoded measurements, gate membership, denominators, population labels, statistical significance, persisted gates, or exported results.

This is not a feature cycle. Confirmed inaccuracies are corrected with fail-closed behavior or with the smallest change that restores the established scientific meaning. Methodological conventions that require a product/science decision are documented rather than silently redefined.

## Confirmed result-changing defects corrected

### A1-01 — Batch Stats family exclusion could remove biologically different samples

The old family heuristic used a generic underscore-prefix comparison. Excluding a file such as `Mouse_01_Control.csv` could therefore exclude `Mouse_01_Treated.csv` merely because both shared two underscore-separated tokens.

**Correction:** family exclusion now applies only to explicit SynaptosomesMacro CytoFile naming families (`_Pooled_CytoFile` and indexed `___CytoFile` acquisitions). Generic prefixes do not imply biological family identity.

**Impact prevented:** missing samples and incorrect batch aggregates.

### A1-02 — GMM Multi could fabricate a separator when adjacent components did not cross between their means

The previous implementation sampled the difference between weighted Gaussian densities and always selected the nearest grid minimum. If one adjacent component dominated throughout the interval, a numeric threshold was still produced even though there was no supported equal-density crossing.

**Correction:** adjacent weighted components must bracket a genuine crossing; the crossing is solved with a root finder. Unsupported pairs emit no threshold.

**Impact prevented:** artificial thresholds and incorrect population splits.

### A1-03 — Degenerate auto-cluster hulls became fabricated rectangles

If `ConvexHull` failed for a collinear/degenerate fitted cluster, vFlow silently substituted the raw axis-aligned bounding rectangle. That rectangle is not an equivalent hull and can contain unrelated events.

**Correction:** an unrepresentable cluster is skipped. `cluster_count` counts only faithfully represented polygon gates. If all fitted clusters are unrepresentable, the existing no-cluster path runs before prior auto-cluster gates are replaced.

**Impact prevented:** silent enlargement of auto-gated populations.

### A1-04 — Rayleigh p-values used a formula inconsistent with the stated Zar/CircStat method

The implemented p-value path used an older `exp(-z)` form plus a differently conditioned correction. Small-sample cases can cross the `p < 0.05` significance boundary differently from the Zar approximation used by CircStat.

**Correction:** use the Zar/CircStat approximation with resultant length `R = n * Rbar`:

`p = exp(sqrt(1 + 4n + 4(n^2 - R^2)) - (1 + 2n))`

**Impact prevented:** incorrect Rayleigh significance classification for affected angular samples.

### A1-05 — Polar centroid auto-detection paired X and Y columns by list position

Valid columns in a different order could auto-select `X_Ch2` with `Y_Ch1`, producing cross-wired displacement vectors.

**Correction:** X/Y columns are paired by shared channel identity, with numeric channel ordering when available. Unusual schemas without a shared identity retain the conservative legacy fallback.

**Impact prevented:** wrong angles, mean direction, MRL, and Rayleigh results from auto-detected mappings.

### A1-06 — Polygon edge/vertex membership depended on winding/orientation

Matplotlib documents exact boundary membership at zero radius as undefined. Exact edge/vertex events could therefore switch IN/OUT when the same polygon vertex order was reversed.

**Correction:** transform-space winding is normalized and an epsilon-scale positive containment radius is used, making exact boundary events deterministically inclusive like rectangle/ellipse boundaries.

**Impact prevented:** orientation-dependent gate membership.

### A1-07 — Transform-invalid polygon vertices could be dropped and the survivors reconnected

A polygon on a scale where one saved vertex is not transformable could previously discard that vertex and evaluate a different polygon made from the survivors.

**Correction:** any transform-invalid applied polygon vertex causes the gate evaluation to fail closed.

**Impact prevented:** silently reshaped gates.

### A1-08 — Nonlinear ellipse preview could disagree with ellipse membership

Ellipse membership and interaction hit-testing use the established raw-data ellipse equation. Matplotlib's `Ellipse` patch transforms Bezier control points under nonlinear axes, which can make the visible log/asinh/biexp/logicle outline diverge from the raw-data population boundary.

**Correction:** linear/linear axes keep the exact legacy patch. If either axis is nonlinear, the preview draws a dense sample of the same raw ellipse perimeter used by the established membership semantics.

**Impact prevented:** a user seeing events inside/outside an outline differently from the statistics that vFlow reports. Existing saved ellipse gates are not redefined.

### A1-09 — Raw duplicate CSV headers could be silently renamed by pandas

Duplicate headers such as `X,X` can be rewritten by pandas to `X,X.1`, changing channel identity instead of reporting the ambiguity.

**Correction:** the raw CSV header is validated before `read_csv`; exact/case-only duplicate headers and multiple ambiguous blank headers are rejected.

**Impact prevented:** silent channel-schema mutation.

### A1-10 — Out-of-range integer FCS measurements could be bit-masked into different values

For `$DATATYPE=I`, values outside the declared `$PnR` range were previously masked according to storage width, potentially turning malformed bytes into another apparently valid event value.

**Correction:** decoded integer events must satisfy `0 <= value < $PnR`; malformed events are rejected rather than altered.

**Impact prevented:** silent numerical corruption of FCS measurements.

### A1-11 — Supplemental FCS TEXT metadata was ignored and duplicate keywords could silently overwrite

Optional supplemental TEXT can contain metadata that changes interpretation or warning state, including gain/channel metadata, timing metadata, or spillover declarations. The primary parser also allowed repeated keywords to overwrite earlier values.

**Correction:** valid supplemental TEXT is parsed before channel naming/numeric conversion; duplicate keywords within a segment or across primary/supplemental TEXT are rejected; offsets are checked against primary TEXT and DATA. The certified FlowJo TextToFCS v1.3 overlapping-STEXT exporter quirk remains explicitly tolerated without adding a new compatibility notice.

**Impact prevented:** missed gain/spillover metadata, duplicate-key ambiguity, and metadata/data-segment confusion.

### A1-12 — Serialized string booleans could invert gate state

Python truthiness makes `bool("false")` true. Malformed/external JSON containing textual booleans could therefore load an unapplied threshold/gate as applied.

**Correction:** gate JSON booleans use a strict compatibility parser for common true/false encodings.

**Impact prevented:** applied-state and threshold-toggle inversion on reload.

### A1-13 — Malformed applied gate JSON could be sanitized into different geometry

Applied polygon vertices or crosshair thresholds could previously be partially dropped while the remainder was accepted. This can load a different gate than the one serialized.

**Correction:** applied geometry/threshold payloads must round-trip losslessly; malformed vertices, thresholds, and threshold-flag length mismatches are rejected. Non-applied legacy gate drafts remain permissive for backward compatibility.

**Impact prevented:** silent gate reshaping during load.

### A1-14 — Multi-gate statistics could collapse duplicate gate names or accept an invalid shape partition

Two different shape gates with the same display name could collapse into the same partition label. Separately, a shape gate that failed to produce `IN` could be treated as all-false and classify every valid event outside.

**Correction:** duplicate shape-gate names are disambiguated with gate IDs before partitioning, and a missing `IN` region raises an explicit error.

**Impact prevented:** merged biological gates and falsely inflated outside populations.

### A1-15 — Batch region masks could overlap while percentages were still reported

A malformed/non-disjoint region mapping could double-count the same event across regions and still produce percentages.

**Correction:** Batch Stats validates region masks as a disjoint partition before calculating the covered event universe.

**Impact prevented:** double-counted percentages and totals.

### A1-16 — Export column normalization could overwrite distinct populations

Batch Plot normalizes `/` and spaces to `_`; distinct names such as `A/B` and `A_B` could map to the same output column. Batch Stats could likewise create the same composite wide-column key from different gate/region combinations when names contained its `__` separator.

**Correction:** both export paths detect final output-key collisions and abort instead of overwriting an existing result.

**Impact prevented:** silently mislabeled or overwritten exported counts/percentages.

## Adversarial verification performed

In addition to the cumulative regression suite:

- randomized weighted-Gaussian crossing checks exercised 20,000 component pairs with no supported crossing disagreement;
- Rayleigh p-values were compared against the reference equation across randomized sample sizes;
- centroid auto-detection was permuted across common Ch1/Ch2 column orderings;
- polygon exact edges/vertices were checked across winding directions and all five current vFlow scale modes;
- 1,500 randomized gate save -> JSON -> reload comparisons preserved membership across crosshair, rectangle, ellipse, polygon and current scale contexts;
- real supplemental-TEXT FCS fixtures exercised gain interpretation, spillover warning detection, duplicate keyword rejection, and the certified TextToFCS overlap quirk;
- the real FlowJo/TextToFCS fixture remains a direct 0.0 DATA-difference decode.

## Deliberately rejected change

A proposed hard requirement that every concatenated CSV have an identical column schema was tested and rejected. Existing valid workflows can contain an additional legitimate measurement column in one source file; forcing exact equality would reject usable data without evidence that the extra column is scientifically invalid. The change was reverted rather than introducing a new assumption.

## Known methodological/interoperability risks not silently changed

### R1 — `biexp` / `logicle` are legacy vFlow signed-log approximations

This was already disclosed in the v4.1.9 README and remains true. The menu names do not imply standards-compatible FlowJo/Gating-ML Logicle/biexponential coordinates. Replacing these formulas would move existing gates and requires an explicit transform migration/versioning decision. For reproducible quantitative work, the existing README continues to recommend `asinh` until such a migration is designed.

### R2 — Polar `Mean_dir_deg` assumes Cartesian +Y-up coordinates

vFlow computes `atan2(Y_Ch2 - Y_Ch1, X_Ch2 - X_Ch1)`. Generic Cartesian tables normally use +Y upward, but ImageJ measurements use an upper-left origin unless its **Invert Y Coordinates** option is enabled. Therefore ImageJ-native Y-down centroids can mirror the reported mean direction across the horizontal axis. MRL and Rayleigh p-value are unchanged by this reflection; angular orientation is not.

This cannot be fixed globally without knowing the coordinate convention of each input. A future scientifically explicit solution should expose/store a coordinate-orientation choice in the polar analysis provenance rather than guessing from column names.

### R3 — Rayleigh test suitability is narrower than “any non-uniform directionality”

The corrected implementation matches CircStat's Rayleigh test, whose documented assumption is a maximally one-mode / von Mises-like alternative. Strongly bimodal or multimodal directional structure can require a different circular non-uniformity test. This is a statistical-method choice, not an implementation bug, and is not silently changed in A1.

### R4 — FCS compensation remains deliberately unapplied

`$SPILLOVER` is detected and warned, but vFlow does not apply compensation. A1 ensures supplemental-TEXT spillover declarations are no longer missed; it does not add compensation behavior.
